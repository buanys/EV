# EV-UI 设计规范 v1.0

> 状态：草案，待拍板
> 适用范围：`:ui-kit`（设计系统）、`ev-ui`（原 eta-ui，默认主页插件）及未来一切 UI 插件
> 目标：深色高级感 · 渐进式简洁 · 液态运动

---

## 0. 设计哲学

三条原则，所有取舍的裁判：

1. **层级靠明度，不靠线条。** 深色界面里，分割线和描边是噪音。分组、层级、可点击感，全部由表面明度差和留白表达。
2. **界面只展示此刻需要的东西。** 高频操作裸露，低频操作折叠在一步可达之处。简洁不是功能少，是功能排队。
3. **一切变化都有物理感。** 没有瞬移、没有匀速、没有与手势脱节的动画。元素有惯性、会变形、跟随手指。

这三条分别对应用户感受：**高级、简洁、活**。

## 1. 颜色系统

### 1.1 深色模式：四级表面阶梯

深色不是纯黑，是四级明度阶梯。层级越深（越"贴近用户"）的元素越亮。

| 令牌 | 用途 | 建议值（默认主题） | 说明 |
|---|---|---|---|
| `surface0` | 页面背景 | `#FF0E0E10` | 不是纯黑 `#000`，留一点明度，让上层元素有处可去 |
| `surface1` | 卡片、消息气泡（对方）、输入框静置态 | `#FF1A1B1E` | 与背景差约 4% 明度，肉眼可辨但不喧哗 |
| `surface2` | 顶栏胶囊、抽屉、弹起面板、输入框激活态 | `#FF232428` | 浮起感 |
| `surface3` | 用户气泡、选中态、按压态 | `#FF2E2F34` | 阶梯顶层，最高明度的"内容表面" |

规则：
- **相邻两级可叠放，跨级叠放要谨慎**（surface0 上直接放 surface3 会"跳"）。
- 纯黑（true black / OLED 黑）作为**主题选项**保留：开启后 surface0 → `#000`，其余阶梯不变。
- 禁用一切纯灰分割线；组内分隔用 `surface2` 上叠 4% 白色雾层（`dividerGhost`），宽度缩进 16dp，绝不贯通全宽。

### 1.2 文本三级

| 令牌 | 用途 | 深色值 |
|---|---|---|
| `textPrimary` | 正文、标题 | `#F2F2F4`（92% 白） |
| `textSecondary` | 副标题、说明、时间戳 | `#B0B1B8`（70% 白） |
| `textTertiary` | 占位符、禁用态、折叠的思考/工具行 | `#7A7B83`（48% 白） |

正文不用纯白——纯白在深色底上光晕过重，长时间阅读刺眼。

### 1.3 强调色（品牌色）

| 令牌 | 值 | 用途 |
|---|---|---|
| `accent` | `#4C8DFF` | 发送键、选中态、链接、焦点、状态胶囊"已连接" |
| `accentSoft` | `accent` @ 16% | 强调元素的容器底（如选中的会话项） |
| `onAccent` | `#FFFFFF` | accent 上的文字/图标 |

纪律：**一屏之内 accent 出现不超过 3 处**。强调色是稀缺资源，用多了等于没有。图标、装饰一律不吃 accent。

Monet 开启时，`accent` 由壁纸取色派生（tonal palette 的 primary 70），其余令牌不动。

### 1.4 语义色

| 令牌 | 深色值 | 用途 |
|---|---|---|
| `success` | `#3ECF8E` | 已连接、保存成功 |
| `warning` | `#F2B84B` | 降级运行（如缺 tools/memory） |
| `danger` | `#F26D6D` | 错误码、删除、权限被拒 |
| `info` | `accent` | 复用强调色，不另设 |

语义色只出现在**状态与操作后果**上，不做装饰。

### 1.5 浅色模式

同一套阶梯翻转：surface0 `#FAFAFB` → surface3 `#ECECEF`，文本三级为深色镜像（`#1A1B1E` / `#5A5B63` / `#9A9BA3`）。accent 不变。
浅色不是本规范的重点交付，但令牌结构必须双模式成立——所有组件**只引用令牌，禁止写死色值**。

## 2. 字体排印

### 2.1 字号阶梯（sp）

| 令牌 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `display` | 28 | 36 | Medium | 空态大标题、欢迎语 |
| `title` | 18 | 26 | Medium | 页面标题、抽屉身份区 |
| `body` | 16 | 26 | Regular | 聊天正文（默认） |
| `label` | 14 | 20 | Medium | 按钮、胶囊、设置行主标题 |
| `caption` | 13 | 18 | Regular | 设置行副标题、时间戳、token 计数 |
| `micro` | 11 | 14 | Medium | 分组标题、徽标、错误码 |

规则：
- 聊天正文允许用户在 90%–120% 之间缩放（沿用现有"界面缩放"设置，改为只缩放 `body` 与 `label` 两级，标题不动，避免布局崩坏）。
- 中文正文行高不小于 1.6 倍字号——这是"阅读高级感"的关键，现在正文偏挤。
- 等宽字体（monospace）只用于：代码块、token 计数、错误码、文件路径。

## 3. 间距与圆角

### 3.1 间距阶梯（dp）

`4 / 8 / 12 / 16 / 20 / 24 / 32` ——七级，组件内外边距必须取自此阶梯。

页面级约定：
- 页面水平边距：`16`
- 卡片/胶囊内边距：水平 `16`，垂直 `12`
- 组与组之间：`24`；组内行与行：`4`（靠容器底色分组，不靠间距撑开）
- 消息气泡间距：同侧连续消息 `4`，换侧 `12`，新一天/新话题 `24`

### 3.2 圆角阶梯（dp）

| 令牌 | 半径 | 用途 |
|---|---|---|
| `radiusS` | 8 | 小元素：徽标、代码内联块 |
| `radiusM` | 14 | 消息气泡（对方）、卡片 |
| `radiusL` | 20 | 面板、抽屉、输入框激活态 |
| `radiusFull` | 50% | 胶囊：按钮、状态指示、顶栏元素 |

细节：用户气泡采用**不对称圆角**——靠发送侧（右下）6dp，其余 18dp，形成"指向性"。连续两条用户消息时，仅最后一条保留下尖角，以上消息全圆角，形成"一簇"的视觉。

## 4. 图标规范

1. **语义唯一性**：一个图标在全局只表达一个含义。当前的心形三用（模型服务/Skills/Eta UI）是反例，全面清理。
2. **来源**：统一使用 Miuix 图标集（`EvIcons`），不足部分以 24dp 网格、2dp 描边、圆头端点的风格自制，禁止引入 `material-icons-extended`（宿主约束已有门禁）。
3. **尺寸三级**：16（行内/消息操作）、20（列表行）、24（顶栏/输入栏）。
4. **颜色**：默认 `textSecondary`，可点击的图标 hover/press 时升到 `textPrimary`；accent 只给"当前选中"或"主操作"。
5. 功能入口图标语义表（草案，实现时逐一确认）：
   - 模型服务：芯片（chip）
   - 工具：扳手
   - 浏览器：地球
   - 记忆：层叠卡片
   - 角色：人像
   - Skills：魔法棒/指令符
   - 设置：齿轮
   - 插件中心：方块网格

## 5. 布局系统

### 5.1 渐进式披露分级

每个功能归入三级之一：

| 级 | 定义 | 呈现 |
|---|---|---|
| L0 常驻 | 每次会话必用 | 裸露在主界面 |
| L1 一步 | 每天会用 | 收进 `+` 面板、抽屉、消息操作行 |
| L2 两步 | 配置类 | 收进设置页、长按菜单 |

判定争执时的默认动作：**降级**。宁可藏深，不可铺满。

### 5.2 三段式顶栏

```
┌──────────────────────────────────────────┐
│ [☰]      [ 上下文胶囊 ]        [ 操作组 ] │
│ 导航      当前模型/会话状态      新会话·更多│
└──────────────────────────────────────────┘
```

- 左段：抽屉入口。有未读状态（如审批待办）时叠加 8dp 圆点（accent）。
- 中段：上下文胶囊，显示当前模型名；未连接时显示"未接模型"（`textTertiary`），已连接时模型名 + success 色小点。**点击 = 打开模型切换**。宽度弹性，超长省略。
- 右段：一颗胶囊容器内放"新会话"和"更多"（⋮），容器 `surface2`，两图标间无分割。
- token 计数：不再常驻顶栏。收进中段胶囊点开的详情卡，或设置-会话页。

### 5.3 拇指区原则

- 屏幕下 1/3 是"做"的区域：输入、发送、主操作。
- 上 1/3 是"看"与"导航"的区域。
- 任何需要频繁点的控件不得出现在屏幕顶部中央以外的地方；破坏性操作（删除会话）永远不在拇指默认落点。

### 5.4 容器化分组

- 相关元素装进同一圆角容器（`surface1/2`），容器即分组；
- 禁止：分组标题 + 通栏列表 + 分割线的"表格化"排布；
- 分组标题如果必须存在，用 `micro` 字号、`textTertiary`，缩进 20dp，距上组 24dp。

### 5.5 空态

空页面不是空白页。每个空态三件套：`display` 标题一句人话 + `caption` 一行引导 + 一个主按钮。例：无会话时——"从一句话开始" / "问问任何事，或让 EV 帮你整理文件" / [开始对话]。

### 5.6 消息流排列

列表**顶部对齐、旧消息在上**：消息按时间正序排列，不满一屏时从顶栏下方开始往下长，不贴着输入栏。

- 反序方案（`reverseLayout = true` + 倒序数据）能让新消息天然贴底，但内容少时会把整段对话压在输入栏上方、顶部空一大片，也与「从上往下读」的直觉相反，不采用；
- 新消息与「正在输入」占位出现时，列表跟随滚到最新一条，不跳转；
- 输入栏与列表是同一列里的兄弟节点：键盘弹起时列表让出高度、内容随之上移。**注意**：若整页被整体顶上去，那是窗口 `adjustPan` 的表现，不是列表排列问题——根因与修复见 `AndroidManifest.xml` 的 `android:windowSoftInputMode="adjustResize"`。

## 6. 运动语言（液态系统）

### 6.1 物理参数（全局唯一）

| 令牌 | 参数 | 用途 |
|---|---|---|
| `springGentle` | dampingRatio 0.8, stiffness 300 | 大面积位移：抽屉、面板 |
| `springSnappy` | dampingRatio 0.75, stiffness 600 | 组件级：按钮、胶囊、气泡入场 |
| `springBouncy` | dampingRatio 0.6, stiffness 400 | 强调时刻：发送、成功反馈（轻微过冲） |
| `fadeFast` | 150ms linear | 纯透明度变化 |

禁止：`LinearEasing` 用于位移；任何超过 400ms 的动画；每个组件自定义弹簧参数。

### 6.2 三条铁律

1. **位移必弹簧**——一切位置/尺寸变化用 spring，出现过冲是特性不是 bug；
2. **形态连续变形**——同一元素的两种状态（胶囊↔卡片、收起↔展开）用 `animateContentSize` / 共享元素过渡，禁止"消失一个、出现一个"；
3. **手势连续性**——可拖拽的元素（抽屉、面板）必须跟随手指，松手带初速度吸附目标态。

### 6.3 组件动效清单

| 组件 | 动效 |
|---|---|
| 消息气泡（新） | 从底部 24dp 位移 + 0.9→1 缩放 + 淡入，`springSnappy` |
| 流式输出 | 高度随文本平滑生长（`animateContentSize`，springGentle），禁止逐帧跳高 |
| 用户消息发送 | 气泡从输入框位置"飞出"，`springBouncy`；输入框内容清空伴随轻微收缩 |
| 抽屉 | 跟手拖拽 + 速度吸附；背景聊天区 1→0.94 缩放 + 8% 变暗，营造纵深 |
| 列表入场 | 错峰浮现：每项延迟 index×30ms，位移 12dp + 淡入（仅首次进入页面，滚动不重演） |
| 状态变化 | 模型胶囊"未接→已连"：宽度、颜色、图标三者同时 spring 过渡 |
| 折叠卡（工具/思考） | 展开高度 springGentle + 内容淡入延迟 100ms |
| 开关/选中 | Miuix 原生弹簧，不另做 |
| 页面转场 | 右进左出 24dp 位移 + 淡入，`springGentle`，无共享元素时不做夸张转场 |

### 6.4 性能红线

- 只动画 GPU 友好属性：`translationX/Y`、`scale`、`alpha`；尺寸动画只用于**屏幕内可见且高度有限**的容器；
- LazyColumn 项不使用 `animateContentSize`（会引发瀑布式重排），新消息入场用 placement 动画；
- 尊重系统"移除动画"无障碍设置：检测到 animator duration scale = 0 时，全部动画降级为瞬时切换；
- 设置页提供"减弱动效"开关（默认跟随系统），开启后弹簧全部替换为 150ms 淡入淡出。

## 7. 组件规范

### 7.1 聊天气泡

- 对方（模型）消息：**无气泡**。左对齐通栏排版，正文 `body`/`textPrimary`，最大宽度屏宽 - 32dp。模型消息是"文档"，不是"对话泡"。
- 用户消息：右对齐气泡，`surface3`，不对称圆角（见 3.2），最大宽度屏宽 78%。
- 消息操作行（复制/重生成/删除）：`micro` 图标 × `textTertiary`，贴消息底部左对齐，默认常显但低明度；点击目标不小于 40dp。
- Markdown：标题不放大超过 `title`；代码块 `surface2` + `radiusS` + 等宽字体 + 右上角复制按钮；列表缩进 20dp。
- 流式时光标：2dp 宽 accent 竖线，500ms 呼吸闪烁，输出结束即消失。

### 7.2 折叠卡（工具调用 / 思考过程 / 审批）

- 收起态：一行，`micro` 图标 + `caption`/`textTertiary` 文案（如"使用了工具：写文件"），行尾箭头；
- 展开态：同容器向下生长为 `surface1` 卡片，内容等宽字体，最大高度 40% 屏高，内部滚动；
- 审批卡常驻展开，含操作按钮 [允许] [拒绝]，按钮为胶囊，`danger` 仅用于拒绝。

### 7.3 输入栏（Composer）

两态连续变形：

- **静置态**：通栏胶囊（`radiusFull`，`surface1`），内含 placeholder、`+`、语音/发送。placeholder 文案轮换（"交给 EV 去完成" / "尽管问，带图也行"）。
- **激活态**（获焦/键盘弹出）：向上生长为圆角卡片（`radiusL`，`surface2`）：输入区独占上部多行，底部一排工具条——左 `+`（附件/工具面板），右语音与发送。
- 发送键：无内容时显示语音图标（`textSecondary`）；有内容时变为 accent 实心圆 + 白色箭头，状态切换用 spring 形变，不是图标替换的硬切。
- `+` 面板：从输入栏位置向上展开的面板（共享边界过渡），网格排列 L1 级功能：附件、工具、角色、Skills。
- 与键盘的关系：输入栏底部 padding 绑定 IME inset，键盘弹出动画期间输入栏**不额外做位移动画**（跟随系统即可），仅做形态过渡——避免双动画抢布局（历史教训）。

### 7.4 抽屉

- 宽度：屏宽 78%，最大 320dp；`surface1`，右缘 `radiusL`。
- 三段结构：
  1. 身份区：EV 标识 + 当前状态一句话（如"本地 · 6 个插件运行中"），`title` + `caption`；
  2. 功能列表：图标 + 文案，行高 52dp，选中态 `accentSoft` 圆角行底；
  3. 会话历史：分组（今天/昨天/更早），选中会话 `accentSoft` + 左侧 3dp accent 指示条；底部固定搜索框。
- 手势：边缘滑动与内容拖拽皆可开启；开合时主内容区缩放 0.94 + 变暗（见 6.3）。

### 7.5 设置页

- 页面结构：分组卡片制——每组一个 `surface1` 圆角卡片（`radiusM`），组间 24dp；组内行间用 `dividerGhost` 雾线（缩进 56dp，对齐文字而非图标）。
- 设置行：左 20dp 图标（`surface2` 圆角方块底 + 图标）+ 主标题（`label`）+ 副标题（`caption`/`textSecondary`）+ 右端箭头或开关。
- 图标底色统一 `surface2`，不再每个图标一个彩色底（彩色底是当前"花哨感"的来源之一）。
- 分组标题：`micro`/`textTertiary`，位于卡片外上方。

### 7.6 状态徽标与 Toast

- 徽标：`micro` 胶囊，`accentSoft` 底 + `accent` 字；语义态用对应语义色的 soft 底。
- Toast/Snackbar：`surface3` 胶囊，底部居中，距输入栏 12dp，spring 上滑入场；错误 Toast 左侧 3dp `danger` 指示条 + 错误码（等宽）。

## 9. 可达性

- 文本与背景对比度：`textPrimary` on `surface0` ≈ 13:1，`textTertiary` on `surface0` ≈ 4.6:1——占位符以外的正文级文字不得低于 4.5:1；
- 全部可点击元素触控目标 ≥ 44dp（视觉图标可以是 16dp，但热区必须达标）；
- 颜色不作为唯一信息载体：状态变化必须伴随图标或文案变化（"已连接"= 绿点 + "已连接"字样）；
- 跟随系统"移除动画"设置（见 6.4）。

## 10. 实施路线图

按依赖关系排序，每阶段独立可交付、可回退：

## 11. 附录：反模式清单（明确禁止）

1. 纯黑 `#000000` 作为唯一背景（除非用户开启 OLED 纯黑选项）；
2. 通栏分割线、彩色图标底块、一个图标多义；
3. 三个以上无层级胶囊在顶栏并联；
4. `LinearEasing` 位移动画、超过 400ms 的动画、组件自定义弹簧参数；
5. 输入栏四个以上常驻按钮；
6. 组件内写死色值/字号/间距（必须引用令牌）；
7. 弹窗确认替代渐进披露（能收进 L1/L2 的不用弹窗）；
8. 空页面留白无引导。
