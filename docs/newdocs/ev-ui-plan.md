# 新 EV 界面总规划（草案 v0.1）

状态：草案，待确认后并入 `docs/规范/`。本文件不改变已定稿的 `ev-final-rules.md`、`ev-manifest-spec.md`、`ev-plan.md`；
凡与其冲突，以已定稿文件为准，并在确认时同步修订。

---

## 一、总原则

1. **宿主拥有所有界面的容器和框架，插件只往宿主给的插槽里投放内容。** 插件不能创建插槽，不能替换宿主的任何外壳。
2. **插槽目录由宿主定义，版本化。** 插件只能引用目录中已存在的插槽 id。
3. **插件投放的是数据，不是控件代码。** 默认使用声明式内容类型，宿主渲染；只有显式声明的插槽允许沙箱自绘。
4. **主题颜色、字号、间距只来自宿主的主题令牌。** 插件内容不允许写死颜色值，由宿主统一渲染时应用。
5. **插槽 id 与宿主渲染器必须一一对应。** 缺少渲染器的插槽或内容类型，在构建期报错，运行时降级为文本，不允许空白。
6. **权限确认、高风险动作确认、安全模式、插件管理，永远是宿主独占。** 任何插槽都不能覆盖它们。

## 二、界面表面归属

| 表面 | 归属 | 插件能做什么 |
|---|---|---|
| 外壳（顶栏、底部导航、页面容器） | 宿主独占 | 无 |
| 引导 | 宿主独占 | 无 |
| 插件管理页 | 宿主独占 | 只展示插件自己的声明信息（名称、版本、权限、状态） |
| 安全模式页 | 宿主独占 | 无 |
| 权限确认、高风险动作确认 | 宿主独占 | 只能发起请求，不能替换界面 |
| 全局通知条、错误提示、降级提示 | 宿主 | 投放文本与动作 |
| 聊天页骨架（消息列表、输入框、滚动、加载与错误态） | 宿主 | 投放消息内容，不替换骨架 |
| 聊天消息内容 | 插件投放，宿主渲染 | 声明式消息内容 |
| 设置 | 宿主留出区块位置 | 声明式配置区块 |
| 插件页面 | 宿主容器 | 声明式页面内容；或沙箱自绘（仅限允许的插槽） |
| 首页卡片 | 宿主 | 声明式卡片 |

**聊天页的骨架归宿主。** 原因：聊天页是主入口，权限确认、错误态、降级提示都要在这里保证一致；如果骨架可替换，这些一致性就无法由宿主保证。

## 三、插槽目录 v1

插槽目录由宿主定义，列出所有可投放位置。每个插槽声明：归属、允许的内容类型、是否允许沙箱自绘、优先级规则。

| 插槽 id | 位置 | 允许的内容类型 | 沙箱自绘 | 优先级 |
|---|---|---|---|---|
| `chat.message` | 聊天消息区 | 文本、工具结果、进度、错误 | 否 | 按时间 |
| `chat.tool-result` | 工具结果的展开区 | 表格、代码块、列表、图片、进度、文件引用 | 否 | 按声明顺序 |
| `page.plugin` | 插件页面容器 | 声明式页面 | 是 | 不适用 |
| `settings.section` | 设置页区块 | 声明式配置结构 | 否 | 按数字优先级 |
| `home.card` | 首页卡片 | 声明式卡片 | 否 | 按数字优先级 |
| `notice` | 通知区 | 文本、动作 | 否 | 严重程度 |

**插槽目录的版本规则：**
- 新增插槽：小版本升级。
- 修改已有插槽的内容类型集合：大版本升级，并给出迁移期。
- 删除插槽：大版本升级，且至少保留一个版本的兼容窗口。

## 四、内容类型（host-api 定义）

内容类型是插件能投放的全部内容形式。宿主为每一个类型提供一个渲染器。

**第一版内容类型（草案）：**

- `text`：纯文本，支持基础强调（加粗、代码样式），不支持任意 HTML。
- `table`：行列数据，列标题必填。
- `code`：代码块，必须声明语言；语言未知时按纯文本渲染。
- `list`：有序或无序列表，项可包含 `text` 与可选动作。
- `image`：只接受宿主可访问的资源引用，不接受任意外链加载。
- `progress`：进度，有确定值与不确定两种。
- `error`：错误，必须包含原因码，可选重试动作。
- `action`：按钮，只能声明意图（如"重试""打开设置"），宿主决定如何执行。
- `file-ref`：文件引用，只显示名称与大小，打开动作交给宿主。
- `settings-form`：设置项集合，项类型只能是：开关、枚举、文本、密钥、数字、只读、状态。

**未知内容类型的规则：** 宿主遇到不认识的类型，统一降级为 `text`，显示类型名与"不支持的内容"提示，并记录一条审计信息。不得崩溃，不得空白。

## 五、渲染与主题

- **渲染器归宿主。** 每个内容类型对应一个宿主渲染器，渲染器只接受已校验的数据。
- **主题令牌归宿主。** 颜色、字号、间距、圆角、阴影都是令牌，由宿主主题提供。插件内容只能引用令牌名，不能写死数值。
- **资源链接不能直接加载外部地址。** 图片和文件由宿主解析为本地资源后再渲染。
- **宿主默认主题**：宿主自带一套默认主题，属于入口的一部分，不可替换，不依赖任何插件。资源插件提供的主题只能覆盖令牌取值，不能改变令牌集合。

## 六、自绘逃生口

- 只允许在声明了沙箱自绘的插槽中使用，v1 只有 `page.plugin`。
- 自绘内容运行在受限容器中，只能通过消息通道与宿主通信，不能直接访问宿主组件或状态。
- 自绘界面必须带有明显的来源标识（例如页面顶部的插件名称），让用户能区分宿主界面与插件界面。
- 自绘界面不能请求权限确认界面的替换，不能伪造宿主的确认对话框。
- 受限档位（子进程）插件不允许自绘。原因：子进程中的界面需要额外的渲染通道，这属于独立立项（见"未决问题"）。

## 七、清单影响

清单需要新增"界面声明"，但它只声明**要在哪个插槽出现**，不声明控件样式。

```json
"surfaces": [
  { "slot": "settings.section", "id": "example.search.settings", "title": "搜索", "content": "settings-form" },
  { "slot": "page.plugin", "id": "example.search.home", "title": "搜索", "content": "declarative" }
]
```

- `slot` 必须存在于宿主插槽目录中，否则拒绝。
- `content` 必须在该插槽允许的内容类型中，否则拒绝。
- 沙箱自绘用 `"content": "sandboxed"`，只允许 `page.plugin`，且插件所在档位必须是可信档位。
- 新增 `surfaces` 字段会改变清单结构，需要 `manifestVersion` 升到 2，并同步更新 `ev-manifest-spec.md` 与清单字段检查。

## 八、内容数据与校验

- 插件投放的内容是结构化数据（JSON 形式），由宿主按内容类型的 schema 校验。
- 校验失败的内容不渲染，改为一条 `error` 类型的内容，原因码记录在审计中。
- 内容数据在插件进程内生成，宿主只接收校验后的副本，不持有插件对象引用。
- 内容数据有大小上限（具体数值为宿主配置项，不硬编码）。

## 九、错误、降级与空态

- 插件未加载或已降级：其投放的内容显示为一条 `notice`，说明插件状态，不留空白。
- 插槽存在但无内容：显示宿主定义的空态，不显示插件内容。
- 渲染器异常：只影响该条内容，显示降级文本，不影响整个聊天页。

## 十、与已定稿规则的衔接

- 插件页面的入口注册沿用登记表规则（页面 id → 入口），不新增登记方式。
- 插件的界面投放不改变激活、停止、隔离的状态机；界面只是服务的一种表现，失效时按降级规则处理。
- 高风险动作的确认走宿主独占的确认界面，插件的 `action` 类型只能发起请求。

## 十一、实施顺序

1. 本草案确认后，并入 `docs/规范/`，同步修订清单规范（升 `manifestVersion`）。
2. host-api：定义插槽目录 v1、内容类型 v1 的契约与版本，写 `api.lock`。
3. host-core：内容校验与未知类型降级策略，纯 JVM 可测。
4. host-runtime / app：宿主渲染器与宿主默认主题，先实现 `text`、`settings-form`、`error`、`notice` 四类。
5. 插件界面投放的端到端测试（JVM 层：数据校验与降级；Android 层：仅编译验证）。
6. 其余内容类型按优先级逐步补齐，每个类型一个门禁。
7. 沙箱自绘：单独立项，不在本规划的前六步内。

每一步完成后停下验证，通过后再进入下一步。真机渲染效果标注「未实测」。
