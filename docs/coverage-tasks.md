> 目的：把"我们觉得能做什么"变成**可数的断点**。判分只看系统状态，不看模型自述。
> 清单落在仓库里，每轮跑完把结果追加到文末；同一个任务断三次，就是机制缺一块。
> 首次建立：2026-11-08。工具面基线：`4751b17`（86 个 `ToolSpec` / 17 个插件）。

## 判分约定

| 记号 | 含义 |
|---|---|
| ✅ | 通过：判分状态成立，且没有人工补手 |
| ⚠️ | 通过但绕路：达成目标多花了步数 / 走了 GUI 兜底 |
| ❌ | 断点：机械不可能（缺工具/缺数据源）、或重复失败 |
| — | 本轮未跑 |

每条的"步数上限"按**人类常用的 2 倍**给（同 AndroidWorld 的约定），超了记 ⚠️。

## 怎么重跑

1. 设备上装当前 release/debug 包，插件齐（`/sdcard/EV/mods`），模型配好；
2. 在 EV 对话框里原样发任务文字（附表里"任务"一列）；
3. 模型要审批时点允许；
4. 用判分依据那一列去**系统里核对**，不看模型的自述；把步数（工具轮数）与耗时填进上表；
5. 断点写清楚：缺工具 / 工具在但没成功 / 模型选错路 / 需要人补手。
