# ADR-0004：执行预算与内存压力（第 5 阶段）

- 状态：已接受
- 日期：2026-11-06
- 相关：ADR-0002（宿主分层）、`docs/newdocs/最高规则` §二（机制 / 恢复）

## 先纠正一个前提

之前我认为"`run_shell` 没有强制寿命"。核对代码后不成立：

- `ShellTools` 的 `timeout_seconds` 默认 30、上限 120，`coerceIn(1, 120)`；
- `ShellRunner` 超时后 `destroyForcibly()`，再 `waitFor(2s)` 收尾；
- 结果里 `exitCode == null` 就是被杀的语义。

所以"长任务会一直挂着"不是当前问题。第 5 阶段要解决的是另外三件。

## 缺口

| 缺口 | 现状 | 后果 |
|---|---|---|
| 没有执行预算 | 插件可以自己 `new Thread` / 建线程池 / 起协程到任意 scope | 一个坏插件能把进程的线程数吃满，宿主没有观测点 |
| 没有内存压力反应 | 宿主不处理 `onTrimMemory` | 系统给信号时，WebView、图片缓存、事件缓冲一个都不缩，最后被 OOM Killer 整个杀 |
| 没有并发准入 | 每个插件想开多少开多少 | 多个插件同时抓网页/跑模型时，内存与调度一起失控 |

## 决策

分三步，每步独立可验证。

### 5a. 内存压力（先做，最便宜）

宿主收到 `onTrimMemory(level)` 时，把系统信号翻译成主动动作：

1. `RUNNING_MODERATE` 起：清图片/位图缓存；
2. `RUNNING_LOW` 起：释放离屏 `WebView`（`HostPageReader` 的实例）、裁剪事件缓冲；
3. `RUNNING_CRITICAL`：停用"非必要"插件（基础插件之外、当前没有前台页面的），
   并在恢复后按需重新激活。

约束：**只缩可再生的东西**。插件数据、会话日志、配置一律不动——"省内存"不能变成"丢数据"。

### 5b. 执行预算（宿主提供，插件声明）

宿主发布一个 `RuntimeBudgetService`：

- 插件通过它拿 dispatcher，**不再自己建线程池**；
- 每次提交带上 `kind`（短任务 / 长任务 / 后台），宿主按 kind 给并发上限与默认寿命；
- 超限拒绝而不是排队（与 DSH 的 admission controller 一致），拒绝理由回给调用方。

这一步不追求"公平调度"。宿主只回答两个问题：**能不能开**、**多久必须结束**。

### 5c. 隔离档位（最后，可选）

受限插件跑子进程 + broker。它的形状取决于 5a/5b 落地后暴露出来的真实压力，
不先设计接口——错误的分层比没有分层更贵。

## 不做

- 不做全局调度器/优先级。宿主管准入，不管排班。
- 不做插件级进程隔离的"默认开启"。它要改变插件加载方式，属于另一个量级。
- 不为了省内存停用正在前台交互的插件。

## 验收

- 5a：在 `RUNNING_LOW` 下手动触发，看到离屏 WebView 被释放、缓冲变小，且聊天与会话不受影响；
- 5b：`RuntimeBudgetService` 有单测（并发上限、拒绝语义、超时取消），且至少一个插件改用它；
- 每个插件卸载后，它提交的任务全部被收掉（可用测试断言）。
