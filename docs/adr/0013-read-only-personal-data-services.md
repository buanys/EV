# ADR-0013：补三个只读的个人数据服务（通讯录 / 短信 / 媒体库）

- 状态：已采纳
- 日期：2026-11-10
- 相关：[ADR-0011 能力面归档](0011-host-capability-catalog-and-version-gate.md)、
  [docs/sdk/host-services.md](../sdk/host-services.md)

## 背景

`docs/sdk/host-services.md` §6 记录过一个判断：宿主"权限齐、服务缺"——
manifest 里 40 条 Android 权限早就声明了，但通讯录、短信、媒体、位置、定时这五类
一条服务都没有。覆盖面清单里 5 条 ❌ 全卡在这里。

本次先补前三个（它们同属"用 `ContentResolver` 读一张表"的形态），
位置与定时留待下一批——那两个分别要 `LocationManager` 和跨重启调度，形态不同。

## 决策

### D1：三个服务都**只读**

`ContactsService` / `SmsService` / `MediaService` 只提供读，接口里没有
`create` / `update` / `send` / `delete`。

理由：写入各自需要 `WRITE_CONTACTS` / `SEND_SMS` / 删除确认流程，宿主**没有声明**那些权限。
与其提供一个必然抛 `SecurityException` 的方法，不如让它根本不存在——
插件作者看接口就知道边界在哪，运行期也不会出现"方法在、权限没有"的半可用状态。

媒体删除还额外一层：Android 11+ 的删除要走 `MediaStore.createDeleteRequest`，
用户在系统弹窗里再确认一次。那是一条独立的交互流程，塞进"读相册"的接口里会
让一个只读服务悄悄变成写服务。

### D2：短信单独一位权限，不并进通讯录

`SMS` 与 `CONTACTS` 分开。一条验证码等于一个账号，而"谁给我打过电话"远没有这么敏感。
用户需要能说"知道谁联系过我，但别看我短信"。

### D3：`MEDIA` 合成一位，不跟着 Android 拆三个

Android 13+ 把图片/视频/音频拆成三个运行时权限，`MEDIA` 仍是一位：
对用户来说"允许看相册"是一件事，拆成三次弹窗只会训练人一路点允许。

### D4：验证码识别放进 `host-core`，做成纯函数

`SmsCodeExtractor` 在 `host-core/personal/`，不在 `host-app` 的 `SmsServiceImpl` 里。

因为这条规则**最容易写错、也最难在真机上验证**：一条短信里同时有订单号、手机号和验证码是常态，
而挑错一个的后果是模型拿着错误数字去登录，报错还指不到这里。
放纯函数里，`11 位手机号不算`、`关键词优先` 这些分支就能在 JVM 上一条条断言，
不必等真机收到某条特定的营销短信。

## 代价与限制

- **`HostPermission` 加常量是契约变更**：旧宿主会拒绝声明了陌生权限的容器（这是设计）。
  所以三个新权限只对 2026-11-10 之后的宿主有效，旧包装上会直接拒绝该容器。
- **首次使用仍要看用户的脸色**：运行时权限在引导页「个人数据」「相册」两组里，
  用户没给时服务会抛 `SecurityException`，插件只能如实报错、不能用 root 绕。
- **`READ_CALL_LOG` 进了 `SMS` 的关联权限**：通话记录这次没做服务，
  但引导页的「个人数据」组已经一并申请了那个权限。以后加 `CallLogService` 时可以复用，
  现在它只是一条已授权但没人用的权限——记在这里以免被当成 bug 清掉。
- **没有分页**：`search` / `recent` 都是 `limit` 截断，没有 offset。
  媒体库上万张图时"翻下一页"做不了，等真需要再加。
